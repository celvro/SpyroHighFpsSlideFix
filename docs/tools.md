# Repo tools and packaging (full details)

Condensed version in CLAUDE.md. This keeps the full notes.

## Repo layout

- `tools/Config.ps1` — shared paths (`$GameDir`, overridable with `$env:SPYRO_GAME_DIR`; `$RepoRoot`; `$BuildDir`)
- `tools/Zip.ps1` — `New-ZipFromEntries` for both packagers: an ordered map of forward-slash entry name → file path, literal text or `$null` (empty entry)
- `ue4ss/Mods/HighFpsSlidingAndJumpFix` — the shipped fixes (released in 1.5.0: braking slide, jump height, walking acceleration and standstill, charge turn slip, mouse charge steering, camera centering, camera centering switch + stuck camera, charge dust, green druid Energize, fire dragon segments, flame breath stray lines, freed dragon walk-in path following, wall slide, glide start and distance, balloon camera spin, Buzz charge run and post-roll braking, Sheila's walking in the Buzz fight; new in 1.5.0: the wall slide, glide start, glide distance, balloon camera, Buzz and Sheila fixes), a UE4SS Lua mod published as "High FPS Gameplay Fixes" (renamed from "High FPS Sliding and Jump Fix" after 1.2.1). The folder and `[HighFpsSlidingAndJumpFix]` log prefix keep the old name on purpose: renaming the folder would leave older installs loading alongside the new one and apply every fix twice (`VERSION` constant in `main.lua`; player-facing `README.txt` ships in the mod folder). `Scripts/` is split into `config.lua` (every `FIX_*` and profiling toggle), `lib/` (log, cached engine handles, `StaticFindObject`/hook bookkeeping, the UE 4.19 movement math), `fixes/` (one module per fix, each headed by the findings that explain it), `profiler.lua` and `main.lua` (the tick). A fix module returns `{ name, enabled, update(ctx) [, reset()] [, disable(ctx, err)] }`; `main.lua` reads the per-frame state into `ctx` once, runs the fixes in order, and on an error takes that one fix out of the rotation after calling its `disable` to undo what it wrote in the engine
- `tools/Find-PropertyParams.ps1 -Exe <decrypted exe> -Names ...` — finds reflected property params (and their offsets) by property name
- `tools/Read-GameVtables.ps1 -ProcessId <pid> [-OutExe <copy>] -Cdos @{...}` — read-only: diffs object vtables from the running game and writes an exe copy with the decrypted `.text` for dumpbin
- `tools/Find-ExeReferences.ps1 -Exe <decrypted exe> [-WideString ...] [-TargetRvas ...]` — finds rip-relative code references to a UTF-16 string or RVA
- `tools/Capture-FlameParticles.ps1 [-Seconds N]` — read-only: samples flame breath particles from game memory (needs the probe's `flame component found ... at 0x...` lines) into `build/probe/flame_particles.csv`
- `tools/Package-Release.ps1` — builds the release zip `build/release/HighFpsGameplayFixes-<VERSION>.zip` (`-ReleaseName`; up to 1.2.1 it was `HighFpsSlidingAndJumpFix-<VERSION>.zip`), laid out relative to the game root (`Falcon/Binaries/Win64/ue4ss/Mods/HighFpsSlidingAndJumpFix/` + `enabled.txt`, forward-slash entries, UE4SS not included). A root `vortex_override_instructions.json` (`setmodtype` `dinput`) makes Vortex deploy it to the game directory: the `game-spyroreignitedtrilogy` extension registers no mod types and defaults to `Falcon/Content/Paks/~mods`, and its `.pak` installer skips this zip, so Vortex's fallback installer copies every entry at its archive-relative path. `dinput` is Vortex core's `modtype-dinput` ("Engine Injector"), a type id unrelated to `dinput8.dll` (its own installer, which does look for that file, is bypassed). Needs a UE4SS experimental build: `LoopInGameThreadAfterFrames` was added Dec 2025 and isn't in stable v3.0.1.
- `tools/Package-UE4SS-Release.ps1` — builds `build/release/UE4SS-for-Spyro-<UE4SS version>.zip` from `tools/bin/ue4ss-dist/`, for a separate "UE4SS for Spyro Reignited Trilogy" mod page. Same game-root layout (`Falcon/Binaries/Win64/dwmapi.dll` + `ue4ss/`). The only change to UE4SS is `MajorVersion = 4` / `MinorVersion = 19` in the packaged `UE4SS-settings.ini` (the source dist isn't touched). UE4SS is MIT, so the zip carries its `LICENSE` both in place and as `LICENSE.txt`, plus `README-ue4ss.txt` (packaged as `README.txt`) with the credits and the list of changes — never strip those. The version comes from `VERSION.txt` in the dist (`-Version` overrides). It also writes `build/release/nexus-description-ue4ss.bbcode` from `nexus-description-ue4ss.bbcode` with `{{UE4SS_VERSION}}` filled in.
- `ue4ss/DevMods/SpyroFpsProbe` — per-frame movement logger for investigating framerate bugs
- `tools/Install-UE4SS.ps1 [-ModsOnly] [-Probe] [-Uninstall]` — installs UE4SS and the Lua mods
- `tools/Save-GameSnapshot.ps1 <name> [-Force]` / `tools/Restore-GameSnapshot.ps1 [<name>]` — named copies of the game's save (`%LOCALAPPDATA%\Falcon\Saved\SaveGames\FalconSave.106.sav`, ~5.9 MB) in `build/saves/`, for repeating tests with enemies, mechanisms and cutscenes reset. Saves hold progress, not position (levels start at the entrance), and only as of the last autosave. Restore refuses while the game runs, copies the current save to `_before-restore` first, and without a name lists snapshots. The save is Steam Cloud synced; restore sets the file time to now so Steam should upload it as the newest local change (not yet tried in practice)
- `tools/Compare-Segments.ps1 -Trace <csv> -Segments <ids>` — side-by-side stats for probe airborne segments
- `tools/DumpInfo/` — minidump reader for game crash dumps (build: `dotnet build tools/DumpInfo -c Release -o build/DumpInfo`)
- `tools/AssetDump/` — C# (.NET 9) reader for cooked UE 4.19 `.uasset`/`.uexp`. It prints imports, exports, tagged properties (including DataTable rows) and, with `--code`, disassembled Blueprint bytecode. Build: `dotnet build tools/AssetDump -c Release -o build/AssetDump`. Run: `build/AssetDump/AssetDump.exe <file.uasset> [--export <name>] [--no-props] [--code] [--hex]`. Cooked function exports have no object-GUID flag, and `UStruct::Children` is serialized as an array.
- `build/` — generated output (gitignored)

## Tooling

- Scripts are PowerShell. Python is not installed (the `python` on PATH is only the Microsoft Store stub).
- There is no pak build pipeline. The unused one (`tools/Build-Mod.ps1` with `mods/<ModName>/`, packing with [repak](https://github.com/trumank/repak) `--version V4 --mount-point ../../../`) was removed; restore it from commit 50c1467 if a fix ever needs an asset or config pak.
- Editing `.uasset`/`.uexp`: use UAssetGUI or FModel with the engine version set to **UE4.19**. Changed assets must stay in the cooked format; replacing a `.uasset` also means shipping its matching `.uexp` (and `.ubulk` if one exists).
